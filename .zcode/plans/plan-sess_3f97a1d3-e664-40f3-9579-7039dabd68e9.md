# План: ITS-test-API — регистрация с авторизацией по ссылке из email

*(обновление: тесты теперь на **testcontainers** — pytest сам поднимает одноразовые Postgres/Redis контейнеры; для тестов нужен только запущенный Docker daemon, без ручного `docker compose up`)*

## Стек (взят из `GrandMotherFilms-/apps/api@dev` один в один)

- **Python ≥3.11, FastAPI, uvicorn**, пакетный менеджер **uv** (`uv.lock`)
- **PostgreSQL** (asyncpg) + **SQLAlchemy 2.0** (Mapped/mapped_column) + **Alembic** (миграции прогоняются при старте, как в образце)
- **Redis** (redis.asyncio) — хранение pending-регистрации `register:{session_id}` с TTL 600с (как в образце)
- **pydantic v2 + pydantic-settings** (валидация email через `EmailStr`), **passlib + bcrypt==4.0.1** (пин как в образце), **python-jose** (JWT в httpOnly-cookie), **jinja2** (email-шаблоны)
- **Gmail SMTP** через `EmailService` из `share/services/email.py` — smtplib, STARTTLS 587, App Password

## Как работает авторизация (адаптация flow из образца под требование «ссылка»)

1. **POST /api/auth/register** `{email, password}` → `EmailStr` валидирует формат (422 при ошибке). Проверка: нет ли уже юзера → `USER_EXIST` 400. Генерируется `session_id = uuid4()`, payload (`email`, `password`) кладётся в Redis `register:{session_id}` c TTL 600с. Рендерится `email_register.html` с кнопкой-ссылкой `{BE_URL}/api/auth/register/confirm?session_id=...` и отправляется через `EmailService` (Gmail SMTP). Ответ `{"ok": true}` 201.
2. **GET /api/auth/register/confirm?session_id=...** (переход по ссылке из письма) → payload достаётся из Redis и сразу удаляется (одноразовость); при отсутствии/истечении → `SESSION_EXPIRED` 400. Создаются `User` + `UserPassword` (bcrypt), создаётся JWT (HS256, `exp = now + 3ч`, `sub = str(user.id)`), роутер коммитит сессию, ставит httpOnly-cookie `access_token` и делает `RedirectResponse("/api/auth/register/success", 303)` — **пользователь авторизован**.
3. **GET /api/auth/register/success** → HTML-страница успеха.
4. **POST /api/auth/login** `{email, password}` → bcrypt-проверка → JWT + cookie (для повторного входа; как в образце).
5. **POST /api/auth/logout** → удаление cookie.
6. **GET /api/user/me** → защищённый эндпоинт через `Depends(get_current_user)` — доказывает, что авторизация работает.

## Сознательные отклонения от образца (и почему)

- В письме **GET-ссылка** вместо POST-формы: требование явно говорит «ссылка»; заодно убираем пароль открытым текстом из письма (в образце это известный косяк).
- Вырезаны payments/videos/celery/S3/Runware/Google OAuth — не нужны по требованиям; послойная структура и идиомы (DI через `get_service`, `BaseRepository`, исключения-константы, коммит в роутере) сохранены полностью.
- `COOKIE_DOMAIN: str | None = None`, `COOKIE_SECURE: bool = False` по умолчанию — чтобы cookie работали на localhost (в образце хардкод `.granny.photos`, secure=True).
- Комментарии/докстринги — минимальные (требование «не вайбкодинг»), стиль именования как в образце.
- `@app.on_event` заменяем на lifespan-обработчик (современно, лишнего не добавляет).

## Docker / deployment

- `deployment/Dockerfile` — двухступенчатая сборка как в образце: builder (`uv venv` + `uv sync --frozen`), runtime (`python:3.11-slim`, curl для HEALTHCHECK на `/health`, `CMD ["python", "src/main.py"]` — миграции прогоняются при старте).
- `deployment/docker-compose.yml` — сервисы: `postgres:16-alpine` (healthcheck `pg_isready`, volume), `redis:7-alpine` (healthcheck), `api` (build context `..`, dockerfile `deployment/Dockerfile`, `env_file: .env`, depends_on healthy, порт 8000). Это и есть «отдельный респект».
- `.env.example` с настройками Gmail: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USE_TLS=true`, `SMTP_FROM=<gmail>`, `SMTP_PASSWORD=<app password 16 символов>`; в README — как создать App Password.

## Тесты (pytest + pytest-asyncio + httpx AsyncClient + **testcontainers**)

- dev-зависимости: `pytest`, `pytest-asyncio` (asyncio_mode=auto), `httpx`, `testcontainers[postgres,redis]`.
- `conftest.py`:
  - **session-scoped fixture** поднимает `PostgresContainer("postgres:16-alpine")` и `RedisContainer("redis:7-alpine")` (тесты сами их стартуют и сносят; нужен только Docker daemon);
  - URL-ы контейнеров прокидываются в env (`DATABASE_URL`, `CACHE_URL` → redis db `/1`), затем модули приложения импортируются заново с чистым `sys.modules` (идиома из `tests/test_runtime_settings.py` образца), чтобы module-level singleton `settings` подхватил контейнерные URL-ы;
  - против контейнерного Postgres прогоняется `upgrade head` через `config/alembic.py`;
  - function-scoped фикстуры: очистка таблиц (truncate) + `flushdb` Redis перед каждым тестом, spy-мок `EmailService.send_email` (реальная отправка не нужна);
  - `httpx.AsyncClient(transport=ASGITransport(app=...))` для запросов к приложению.
- Интеграционные: регистрация (валидация email 422, дубликат 400, успех + письмо «отправлено» + сессия в Redis), подтверждение по ссылке (создание юзера, cookie `access_token`, одноразовость сессии, битый session_id → 400), логин (успех/неверный пароль/несуществующий юзер), `/me` (200 с cookie / 401 без), `/health`.
- Юнит: JWT create/check + истечение срока.
- Запуск: `uv run pytest` — единственное требование, запущенный Docker daemon.
